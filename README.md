# aws-game-lists

Список публичных IPv4-подсетей AWS для обхода блокировок в играх, серверы которых
живут на Amazon. Собирается из официального `ip-ranges.json` — объединение тегов
**AMAZON + EC2 + GLOBALACCELERATOR**.

Нужен там, где фильтровать по доменам невозможно: игровой UDP-трафик не содержит
ни SNI, ни имени хоста — матчмейкер отдаёт клиенту голый `IP:порт`. Хостлист по
такому трафику не работает в принципе, остаётся только список сетей.

## 🌐 Для Podkop

Сети:

```
https://raw.githubusercontent.com/akorshun/aws-game-lists/main/results/cidr_ipv4.txt
```

## ⚠️ Важно: список широкий

Это **весь публичный AWS**, а не только игровые серверы. Отдельного тега для
GameLift в AWS не существует, флоты крутятся на обычных EC2-инстансах вперемешку
с чем угодно ещё, так что выделить из них игровые нельзя.

Практический вывод:

* **Для zapret / GoodbyeDPI в качестве ipset игрового UDP-фильтра — подходит.**
  Там список работает в паре с фильтром по протоколу и портам, и лишнего почти
  не захватывает.
* **Для маршрутизации всего трафика (Podkop, VPN policy routing) — применяйте
  осознанно.** На AWS стоит заметная часть интернета, включая CDN и API кучи
  сервисов. Загнав этот список в туннель, вы отправите туда сильно больше, чем
  игры.

## 🎮 Для каких игр

Критерий один: серверы игры хостятся на AWS. Список покрывает всё адресное
пространство Amazon, так что подходит любой такой игре.

**Проверено измерением:**

* **Dead by Daylight** — выделенные серверы на AWS GameLift. Матч снят пакетным
  захватом, сервер оказался в `18.192.0.0/15` (eu-central-1).

**Вероятные кандидаты** (по публично известной инфраструктуре, замерами здесь не
подтверждались — проверяйте скриптом):

* тайтлы на AWS GameLift;
* игры Amazon Games — New World, Lost Ark;
* проекты, где выделенные серверы подняты на EC2.

**Как проверить свою игру наверняка:** запустите `disconnect-hunt-30min.ps1`,
сыграйте матч. Скрипт покажет IP игрового сервера и скажет, попадает ли он в
список. Это занимает полчаса и даёт однозначный ответ вместо догадок.

## 🛠 Скрипты

| Скрипт | Зачем |
|---|---|
| `scripts/disconnect-hunt-30min.ps1` | Ловит вылеты, показывает IP серверов и покрытие списком. 30 минут. |
| `scripts/disconnect-hunt-2h.ps1` | То же на 2 часа — когда вылеты редкие, раз в 3-4 матча. |
| `scripts/update-list.ps1` | Пересобирает `results/cidr_ipv4.txt` из свежего `ip-ranges.json`. |

Скрипты отлова требуют **PowerShell от администратора** (используют `pktmon`,
встроенный в Windows 10 1809+ / 11). Список качают сами, локальный можно указать
через `-Ipset`.

Двухчасовая версия пишет в кольцевой буфер и проверяет свободное место: игра даёт
около 28k сэмплов в минуту, а расшифровка pktmon — примерно 800 байт на сэмпл, так
что два часа это 2-3 ГБ текста. Буфер по умолчанию 2 ГБ, менять через `-EtlSizeMB`.
Поймав вылет, можно смело жать Ctrl+C — нужное уже в буфере.

Пример:

```powershell
.\disconnect-hunt-30min.ps1
.\disconnect-hunt-2h.ps1 -Minutes 90 -KeepRaw
.\disconnect-hunt-30min.ps1 -Ipset "D:\zapret\lists\ipset-dbd-all.txt"
```

## 🔄 Обновление

AWS правит `ip-ranges.json` несколько раз в неделю, новые диапазоны появляются
регулярно. Если игра внезапно начала выкидывать — первым делом обновите список:

```powershell
.\scripts\update-list.ps1
```

Скрипт откажется перезаписывать файл, если распарсилось меньше 3000 префиксов:
лучше остаться со старым рабочим списком, чем получить пустой из-за смены формата.

## 📐 Почему объединение трёх тегов

Первая версия списка фильтровала только по `EC2` — 1900 префиксов. Результат:
2-3 матча идут нормально, потом вылет в середине игры, следом выкидывает и из
лобби (в DBD лобби живёт на том же инстансе GameLift, что и матч).

Причина в том, что `EC2` — это лишь 1900 из 6109 префиксов AWS, а игровые серверы
спокойно попадают в диапазоны с тегом `AMAZON`. Две трети адресного пространства
оставались непокрытыми, и как только матчмейкинг переселял на такой сервер, канал
умирал.

При этом `AMAZON` не является строгим надмножеством `EC2`: 46 префиксов `/32` в
диапазоне `99.77.55.x` помечены только как `EC2`. Поэтому нужно именно объединение,
взять один самый широкий тег недостаточно.
